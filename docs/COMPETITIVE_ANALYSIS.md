# Fractal Competitive Analysis

**Research date:** 2026-11-04  
**Scope:** Scramjet source in this checkout (`@mercuryworkshop/scramjet` 2.0.67-alpha.2), the public Scramjet and Ultraviolet READMEs, Fractal workspace source, and the standards listed under References. No live third-party site was accessed for compatibility testing.

## Evidence Labels

- **VERIFIED:** directly present in inspected source, manifest, or normative specification. This does not imply a browser integration test passed.
- **OBSERVED:** recorded by the repository's Runway expected-failure ledger or a test annotated as a known failure. Those cases were not rerun in this research session.
- **HYPOTHESIS:** plausible engineering consequence requiring a controlled test or measurement.
- **NOT TESTED:** no result is available in this checkout/session.

Scramjet's upstream README calls it experimental and describes interception, rewriting, and sandboxing. It lists Google, YouTube, Discord, and GeForce NOW as supported sites; that list is a project claim, not evidence that each feature flow passed. The local Runway site tests cover basic Google and YouTube page signals, not end-to-end account, media, messaging, or game-streaming behavior. The local Scramjet source is AGPL-3.0-only per its manifest; this analysis records behavior and does not copy its implementation.

## Browser and Protocol Constraints

- Service workers require secure contexts and registration/script/scope origin rules. They control clients in their registration scope; they are not a browser-wide arbitrary proxy. See the [Service Worker explainer](https://github.com/w3c/ServiceWorker/blob/main/explainer.md) and [specification](https://w3c.github.io/ServiceWorker/).
- The Fetch standard defines `follow`, `error`, and `manual` redirect modes. Browser `manual` mode yields a filtered redirect response; a server-side Fetch runtime can expose a different implementation surface. See [Fetch redirect mode](https://fetch.spec.whatwg.org/#concept-request-redirect-mode).
- The WebSocket constructor exposes a URL and optional subprotocols, not arbitrary request headers. Authentication must use a supported browser/server design rather than assuming header injection. See the [WebSocket standard](https://websockets.spec.whatwg.org/).
- WebTransport is marked secure-context-only in its API definitions and provides transport streams/datagrams over supported HTTP/3 or HTTP/2 connections; HTTP/3 uses QUIC. See [WebTransport](https://w3c.github.io/webtransport/), [RFC 9114](https://www.rfc-editor.org/rfc/rfc9114), and [RFC 9000](https://www.rfc-editor.org/rfc/rfc9000).
- WebRTC uses its own peer-connection/ICE mechanisms. A Fetch or service-worker proxy does not imply transparent handling of media/data paths. See [WebRTC](https://www.w3.org/TR/webrtc/); deployment behavior is browser/network-dependent and **NOT TESTED**.
- HTTP caching semantics are governed by [RFC 9111](https://www.rfc-editor.org/rfc/rfc9111); HTTP/2 multiplexing and connection reuse by [RFC 9113](https://www.rfc-editor.org/rfc/rfc9113); HTTP/3 transport mapping by [RFC 9114](https://www.rfc-editor.org/rfc/rfc9114). Protocol support alone does not establish a performance advantage.
- Import-map resolution is specified by [HTML](https://html.spec.whatwg.org/multipage/webappapis.html#import-maps); CSS tokenization by [CSS Syntax](https://www.w3.org/TR/css-syntax-3/); content policy and integrity by [CSP Level 3](https://www.w3.org/TR/CSP3/) and [Subresource Integrity](https://www.w3.org/TR/SRI/).

## Research Conclusions

1. **VERIFIED:** Scramjet is not just URL rewriting; this source snapshot combines a service-worker request path, response rewriting, browser API interception, a WASM/Oxc JS rewriter, and an external Bare-compatible transport.
2. **OBSERVED:** the expected-failure ledger tracks dynamic import maps, module-worker imports, CSS comment rewriting, and the page-visible ServiceWorker API. Fetched-module `import.meta.url` is only annotated as a failure in test commentary and is absent from that ledger. None of these cases was rerun here.
3. **VERIFIED:** CSS uses regular expressions where JavaScript uses an AST pipeline. This is a concrete architectural difference; any performance or compatibility consequence must be measured.
4. **VERIFIED:** Fractal source/manifests are separate from Scramjet rewriter/runtime packages. This proves a package boundary, not a complete browser-engine replacement.
5. **NOT TESTED:** no equivalent browser-site compatibility or performance measurements exist for either engine in this session. No statement that Fractal is faster, safer, or more compatible is supported.
