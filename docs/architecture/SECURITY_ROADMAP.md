# Fractal Security Roadmap

**Status:** assessment and plan, 2026-11-04. This is not a security certification or penetration-test report. Fractal must not be exposed as a public relay.

## Current Boundary

The example server binds to `127.0.0.1`, exposes a fixed local fixture, and rejects destinations outside the exact fixture origin and fixed route table before Fractal dispatch. Its server-side redirect loop checks every redirect against the same table. Fractal `FetchTransport` itself supports an origin allowlist, literal-host checks, manual redirect responses, request/upload/response byte caps, timeouts, and abort signals.

Fractal's generic Fetch transport does **not** resolve DNS and pin a socket to a validated address. Its literal IP checks are not a complete reserved-address policy. It has no gateway authentication, per-user identity, rate limiter, global in-flight byte budget, or server-derived cache partition. The generic Core returns redirects rather than following and revalidating them. No cookie-virtualization or production CSP/SRI model exists. The example is safe only as a loopback fixture environment, not as evidence that generic remote proxying is safe.

## Required Before Any Remote Gateway

| Risk                        | Gap                                                                                                                                                                          | Required control and gate                                                                                                                                                                                                                                                                   |
| --------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| SSRF/DNS rebinding          | Host allowlisting alone does not bind DNS answers to the opened socket.                                                                                                      | Resolve A/AAAA at connection time, reject unsafe addresses, pin the actual connection to validated results while preserving TLS SNI/Host, constrain ports/schemes, and re-check every connection/redirect. Test with a controlled resolver that changes answers between lookup and connect. |
| Address classification      | Existing checks cover only selected literal forms; IPv4-mapped IPv6, alternate encodings, reserved ranges, and special-purpose ranges need a single canonical parser/policy. | Use a maintained IP/CIDR parser; canonicalize URL host first; deny unspecified, loopback, private, link-local, multicast, documentation, benchmarking, reserved, and metadata ranges by policy. Add exhaustive IPv4/IPv6 vectors and property tests.                                        |
| Redirect abuse              | Generic Core returns the redirect response; another caller could follow it incorrectly.                                                                                      | Put redirect resolution/revalidation in the trusted gateway/transport layer; cap hops, bytes, elapsed time, and scheme transitions; strip/recompute credentials and origin-sensitive headers on cross-origin hops.                                                                          |
| Authentication              | No Fractal gateway auth/authz exists.                                                                                                                                        | Authenticate before request admission; derive principal and quotas server-side; authorize each destination and WebSocket; prevent anonymous use; rotate/revoke credentials and audit without logging secrets.                                                                               |
| Cross-user leakage          | Cache partitions are caller-provided.                                                                                                                                        | Derive partition from trusted identity plus isolation context; do not accept client-chosen partition labels as authority; test concurrent cross-tenant cookies, auth, cache hits, and cancellation.                                                                                         |
| Resource exhaustion         | Queue and per-response sizes are bounded, but aggregate in-flight memory, rate, bandwidth, CPU, parser work, and user concurrency are not.                                   | Add global/per-principal byte budgets, rate/concurrency quotas, parser depth/token limits, deadlines, idle connection caps, and load shedding. Stress test slow readers and many near-limit responses while sampling RSS/heap.                                                              |
| Header and cookie confusion | No production header policy or cookie jar/session model.                                                                                                                     | Strip hop-by-hop/proxy-internal headers, control Host/Forwarded/Sec-Fetch fields, isolate cookie jars, define SameSite/referrer behavior, prevent credential forwarding across origins, and redact diagnostics.                                                                             |
| CSP/SRI                     | The legacy implementation removes some policies; Fractal has no content rewriting/security translation yet.                                                                  | Do not strip policies generically. Define how CSP, SRI, sandbox, COOP/COEP/CORP, and MIME protections survive transformed bytes; deny unsupported active documents rather than claiming secure delivery.                                                                                    |
| Concurrent navigation       | App request sequence and AbortSignal prevent stale result display; runtime resource requests have their own bounded request lifecycle.                                       | Add race tests for delayed headers/body, user cancellation, timeouts, server shutdown, and stale iframe load events; ensure old responses cannot write state or diagnostics as current.                                                                                                     |

## Deployment Stages

1. **Local fixture:** loopback binding, fixed files/routes, no arbitrary target; current example. This is the only supported deployment stage today.
2. **Trusted development gateway:** authenticated operators, fixed allowlisted origins, DNS pinning and redirect validation, private-network deny by default, short quotas, isolated test accounts, redacted audit trail.
3. **Private pilot:** independent security review, per-user quotas, incident response, abuse monitoring, pinned resolver/connection behavior, tenant cache/cookie tests, compatibility suite, reproducible load tests.
4. **Production:** formal threat model, external review, key lifecycle, monitoring/alerts, abuse response, privacy/data retention policy, deployment hardening, regular regression and dependency review.

## Security Test Matrix

- Unit: canonical URL parsing, hostname normalization, IPv4/IPv6/CIDR cases, DNS answer sets, forbidden ports/schemes, userinfo, invalid IDNA, redirect resolution.
- Integration: controlled DNS answers change across connections; every redirect is checked; public-to-private and private-to-public transitions; blocked metadata fixture; oversized streamed body; slow consumer; cancellation and timeout.
- Isolation: two authenticated principals with same URL but different cookies, headers, cache partitions, WebSockets, and simultaneous requests.
- Browser: sandbox flags, opaque frame origin, CSP enforcement, no direct outgoing requests, blocked top navigation/forms, user-gesture behavior, CSP/SRI outcomes.
- Operations: unprivileged process, loopback-only dev bind, no tokens in logs, bounded telemetry, safe shutdown and cache cleanup.

Only controlled local fixtures and synthetic DNS data should be used. Do not probe third-party networks or metadata endpoints as a test method.

## Status

- DNS pinning: **NOT IMPLEMENTED**.
- Gateway authentication/authorization: **NOT IMPLEMENTED**.
- Production SSRF controls: **NOT IMPLEMENTED**.
- Example exact local fixture allowlist and redirect revalidation: **IMPLEMENTED AND TESTED**.
- General remote browser navigation: **NOT IMPLEMENTED**.
- Public deployment: **PROHIBITED by current design**.
